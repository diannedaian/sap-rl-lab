# 40 宠稳定性：先探索对照，再独立确认

用户授权夜间继续排查策略坍缩和循环，目标是给下一轮扩展确认有证据支持的
训练配方，而不是只交付一个幸运模型。旧 40 宠实验、权重和测试结论保持冻结。
本文件不预先宣称稳定性已解决。

## 第一阶段：成绩产生前固定的小试

- 只用原 40 宠实验的混合训练池：三脚本、三学习型来源等权。历史阵容是对手，
  不是模仿数据。复制原训练/验证池并记录摘要；不读取旧测试成绩来选新配方。
- 三对从零模型：原失败种子 17301，以及新种子 17401、17501。
  每对只改变 entropy coefficient：0 对 0.01；配对初始权重和验证逐局结果需一致。
- 各固定 1,048,576 次决策，共 6,291,456 次；每 262,144 步验证四家族各
  100 局，验证 episode seed 从 19,000,000 开始。观察最终更新前后以及完整曲线。
- 其余继承：小 Maskable PPO、学习率 3e-4、gamma=1、GAE 0.95、8 环境、
  rollout 256、batch 256、每动作 −0.005、30 动作强制战斗。不加剩钱扣分、
  购买奖励、禁止结束回合等规则，不修改动作掩码来掩盖失败。
- 主要诊断：零胜且全局没有购买宠物的失败比例；辅以平均胜场、十胜率、
  宠物购买数、强制整局比例、截断。低强制率或购买数增加单独不代表成功。
- 各模型仍按既有验证规则保存最佳和最终版本，最佳重载逐局核对。
  17301 是已知故障复现，不冒充全新独立种子。
- 最多两个本机 CPU 训练进程，每对一小时超时，出错停止，不自动换种子、
  重试、延长预算或发布模型。入口：
  `python -m sap_rl_lab.exploration_pilot pipeline --output runs/exploration-pilot-v1`。

## 后续仍必须完成的工作

1. 结合动作概率、回放和曲线审查：是否真减少空队伍失败，是否只是换成冻结循环。
   0.01 是一次候选设置，不是最优值；熵为 0 也不等于原训练完全没有随机探索。
2. 如需补充实验，每次明确具体失败机制和单一改动；先记录假设、预算、指标，
   再启动，避免同时改奖励、网络、学习率而无法解释。初步限两轮额外小试，
   不能把重复换种子当修复。若仍失败，报告证据不足，不凭最好一局确认配方。
3. 小试不足以确认下一轮 recipe：必须固定候选，用新训练种子跑到完整预算，
   与继承配方配对比较，并用不参与调参的新留出对手/episode 验证。确认计划、
   失败判定及胜率/强制权衡必须在确认成绩产生前写明。
4. 确认阶段要审查所有种子、最终和所选检查点、成功和失败回放。保留失败种子，
   检查后期是否又坍缩；不沿用被诊断过的旧测试集作为独立证明。
5. 最终给简明中文报告：修复了什么、仍有什么失败、证据强度、能否确认下一轮
   扩展配方。若能确认，写出精确配置与选择规则；不意味着保证所有新环境稳定。

## 确认阶段的预定规模与判断边界

这些边界在确认训练和确认对手成绩产生之前写明。小试结束后再固定唯一候选
配方及实际执行协议；下述规模不是现在已经启动的实验。

- 计划五个全新配对训练种子，每对比较继承配方和候选修复；两边都使用相同
  混合对手分布、初始权重、训练预算和选模规则。每模型固定 8,388,608 步。
- 两个新学习型留出生成者各固定 4,194,304 步，取最终权重，候选不得使用
  它们训练或选模；另有三个新脚本测试池。测试各模型每家族 1,000 局，共
  50,000 局。生成者强度、空队伍比例与后期覆盖须检查，不能拿坍缩的弱对手
  证明候选更强。所有候选先冻结、全部重载核对后才打开测试。
- 确认配方至少要求：五个候选均没有整种子空队伍坍缩；各测试家族无购买零胜
  比例不超过 1%；独立学习型十胜率平均不低于配对基线，至少四对差值非负；
  各候选各家族强制整局比例不超过 2%，测试零截断。完整预算最终检查点也要
  检查空队伍坍缩，不能只报告中途好的版本。
- 2% 是事先给这次确认设置的工程警戒线，接受原先 1% 与 1.5% 这种小差异，
  但不接受明显依赖强制推进的策略。它不是统计定理或完整 Turtle 的永久指标。
  若强度/稳定性有冲突，照实报告未通过，不能看完测试再放宽判定或换检查点。
- 同时报告每对、最弱家族和区间；五个种子仍不足以保证所有初始化与扩展环境
  都稳定。通过只支持把精确配方作为下一内容阶段的起点，并需重新验证。
- 第一轮小试 + 最多两轮同规模补充小试 + 一轮上述确认，训练上限约 1.112 亿
  次决策。未用到的补充小试不执行；不因失败自动扩预算。最多两个 CPU 工作者，
  不使用集群、GPU、外部发布或覆盖已有实验目录。

参考：SB3-Contrib 的 [Maskable PPO 参数说明](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html#parameters)
将 ent_coef 定义为损失函数中的熵项系数。本轮选择基于实际早期坍缩证据，
不是文档保证 0.01 在本沙盒有效。

## 小试审查后固定的唯一补充比较

第一阶段六模型已跑满并重载一致；14,400 条验证记录重新计数一致，15 个最终
模型回放精确复现。0.01 救回 17301，但新种子 17401 平均胜场下降且强制上升，
17501 则略改善；强制回放包含真实重复冻结/换位，而不是仅有正常购物。
详见 [进度与结果](EXPLORATION_STATUS.md)。

因此把原定两轮各约 629 万步的补充预算，合并为**一次 0.003 对 0.01、每模型
2,097,152 步**的六模型比较，总计 12,582,912 步，不增加总预算。仍用
17301/17401/17501 从零配对，不继承小试额外训练，不改奖励或规则；每 524,288
步验证。它同时检验较低探索的取舍，以及当前强制是否只是短训练阶段现象。
两臂同一预算，因此不能拿旧 105 万步对照直接当成 210 万步的公平比较。

入口：`python -m sap_rl_lab.exploration_sensitivity pipeline --output runs/exploration-sensitivity-v1`。
该比较结束并审查后只选一个候选进入预定的新种子完整预算确认，不继续搜索其他
熵系数。若没有有依据的候选，明确报告仍未解决，不假装确认成功。
