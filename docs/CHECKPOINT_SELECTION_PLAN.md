# 追加只读对照：先可靠性，再比胜率

这不是替换或重启正在运行的五对熵系数确认，也不增加训练决策预算。主实验结果
仍完整保留。此计划在任何主实验模型测试开始前写明；追加分析最多两路本地 CPU，
只在主实验进程正常结束后运行，不发布或覆盖模型。

## 为什么需要

第二对原配方在 5,242,880 步的验证共 716/800 局十胜，最差家族强制率 2%；
最终更新前为 717/800，强制率却为 65%。现行胜率绝对优先规则选择后者。一个
额外十胜就覆盖这么大的效率差异，说明选模规则与我们声明的运行要求可能不一致。
不能据此推断全部训练不稳定都由选模造成。

较早的每次验证权重没有全部独立保留，不能声称能直接恢复那个 2% 的版本。
追加对照只使用实际保存的权重，不重训来重造历史模型。

## 固定比较

- 仅使用主实验五个 `control` 训练种子：201101、201201、201301、201401、201501。
  这隔离选模规则，熵系数都为 0。主实验的五个 0.01 候选仍照原流程评估，不能
  因本追加对照而隐藏其失败或把它们说成通过。
- 每个种子的候选集合相同：十个实际周期存档，加原 `best_model` 和 `final_model`。
  十个周期为 `838856 × 1…10` 步；载入时核对真实步数、模型摘要和冻结配置。
  两种选择规则看到完全相同的一组权重，避免把检查点覆盖差异混入规则效果。
- 这组存档统一使用原验证四家族、每家族 200 局、episode seed 22,000,000。
  周期权重重新验证；原 best/final 的已有验证需重计核对，并记录来源摘要。
- `win_first`：现行 v5 十胜率、最弱家族、强制率、原始回报排序。
- `reliability_first`：先要求各验证家族强制整局率 ≤2%、无购买零胜失败率 ≤1%、
  零截断，再用完全相同排序。沿用已经声明的工程线，不在看测试后调线。
  精确平局选实际保存步数较早者，再按稳定的文件标识排序。
- 没有合格权重就记为该种子失败，不换种子、不回退到不合格模型、不从比较中
  删除。筛选不等于修复所有学习过程，也不保证有可交付模型。

## 隔离与预算

- 主实验进程可能先自动生成其测试文件，但在本追加选择全部冻结前，代理不读取
  主实验测试指标或总结。追加程序只读其训练、验证、完成标记和冻结对手，不读
  主实验的 `test-*.json` 或 `confirmation_summary.json` 来选模。
- 五个种子、两种规则全部选择冻结，所选权重各自重载复现 800 局验证之后，才能
  开始追加测试。完全相同的选择可以复用同一份重载和测试，避免重复运算。
- 追加测试使用原冻结的五个测试对手池，但用新的 episode seed **25,000,000**，
  每家族 **400 局**；不生成新对手、不把测试阵容加入训练。对手来源和后期覆盖
  局限仍与主实验相同，这不是无限分布上的泛化证明。
- 额外预算上限：周期验证 40,000 局、所选重载 8,000 局、测试 20,000 局；训练
  更新 **0**。两路 CPU，单个双工作者阶段两小时超时，出错停止，不自动加预算。

## 如何判断

所有五个可靠性优先选择都必须存在；各测试家族无购买零胜失败 ≤1%、强制整局
≤2%、零截断；原训练最终验证不能有 >1% 的无购买零胜复发。对两个学习型测试
家族，相对相同候选集合下 `win_first` 的平均十胜率差值须非负，至少四对非负。
这只是工程筛查，不自动确认配方。若有缺失选择，完整列出失败种子，不只汇总
剩下的成功模型。

报告五个种子、各家族整数计数、每家族配对 episode bootstrap（2,000 次）和
五训练种子 bootstrap（10,000 次、随机种子 25,500,000），区分两类不确定性。
最终还要审查回放、实际效果大小和失败模式；若胜率与可靠性发生取舍，照实报告，
不看完测试再放宽判定。结果只支持或反对这个具体的选模配方，不能宣布高熵训练
本身被修好，也不能用筛选掩盖原始训练方差。

## 执行与防误用

实现为 `scripts/compare_checkpoint_selection.py`，登记目录为
`runs/checkpoint-selection-v1`。先运行 `register` 固定本计划、执行脚本及其审查
依赖的摘要，并拒绝已经存在主实验测试开始标记的登记。只有主实验正常结束后
才运行 `pipeline`；启动前由代理核对原进程确已退出。整个程序没有训练调用。

流水线顺序为：核对全部实际存档 → 周期验证及缓存重计 → 冻结全部选择 → 全部
所选模型精确重载 → 新 episode seed 测试 → 比较汇总。任一阶段失败停止，输出
新文件不覆盖旧结果。缺失合格选择会保留在最终五种子表中，并禁止仅对剩余种子
计算总体改善。摘要仍保留 `recipe_confirmed: false`，等待证据和回放审查。
