# 历史对手混合：下一轮小试

2026-09-07。用户已同意启动；先完成小试和审查，再启动正式训练。

## 这次只改训练对手

- 现有 30 宠课程、普通商店 Tier 2 上限、30 步强制战斗保持不变。
- 两组都每步扣 0.005，使用相同 PPO、网络、学习率、批量和折扣。
- 小试从交付模型 action_cost-seed1907 的策略和价值网络权重初始化。
  两组均重置优化器，使用相同新随机种子 8101，而非继续旧优化器状态。
- A：原三个脚本来源等权；B：三个脚本 + 三个历史模型来源等权。
  因此 B 在每场战斗处以 50% 概率选脚本、50% 选历史模型阵容。
  不按阵容数量给来源加权，不搜索混合比例。
- 每组 1,048,576 次新决策，最多两个本机 CPU 工作进程。
  每 262,144 步及训练前后验证；没有 GPU 作业或集群操作。

## 来源与隔离

训练生成者预先选为 v8 action_cost、v8 swap_cost、confirmation-v3 control1811：
覆盖不同奖励训练史及不同初始化，但不能预先保证三种独立打法。
每个模型从新种子 8,800,000 开始运行 120 局，保存所有实际战斗前阵容，
包括失败局和强制结束商店的战斗。它们经营商店时面对相同原脚本混合。
生成结果被冻结，学习者在其上打新对局；不是用旧动作记录训练 PPO。

验证使用原三个脚本验证池和未参与训练池的 control1907 生成者；
后者从 8,900,000 开始生成 60 局。每次验证四个家族各 60 局，
新评测种子从 9,000,000 开始。选模按四家族等权的无强制十胜率，
再按原始回报，平分保留较早版本。初始模型也参与选模，不能只报聚合分数。
注意：验证中脚本占 3/4 权重，和训练的 50/50 并不相同；两组完全共用此规则。

复制并核验三个未来配对初始模型和各生成者，按策略张量摘要检查角色不重叠。
control2027 暂保留为最终测试来源，小试不生成、不查看其挑战分数。
旧 v8-control 的 40% 挑战已被检查过，以后只能作开发/回归诊断。
正式实验前仍需补齐多个留出生成者的最终测评设计；不能用 control2027
一个生成者就宣称广泛泛化。现有模型共享算法和训练背景，角色隔离不等于
完全独立的策略家族；配对 control/action 还共享原始种子，这一限制必须披露。

## 对偏差的检查

每个阵容附来源模型、规则摘要、回合、战前胜场/生命、金币和回合动作数；
每局记录动作类型计数。报告各回合覆盖、宠物分布、相同回合完整阵容重复率，
以及缺失回合时实际会回退到哪个较早桶。战绩只记录，不擅自改变匹配规则。
后期阵容是“走到后期”的条件分布，少量快照和同源打法仍可能带来偏差。

## 小试结束后的门槛

核对完整相同预算、相同初始参数及初始逐局验证；选中模型重新加载后逐局复现。
人工审查分家族学习曲线、强制战斗/截断、耗时和上述覆盖报告。
这一个配对小试不做显著性或最终泛化结论，也不会自动派发正式实验。
正常后按原方案推进三组配对起点、每组 8,388,608 次决策；重新从原模型开始，
不继承小试额外训练步数。最终先冻结选模，再打开测试。

实现入口：`python -m sap_rl_lab.generalization pilot --output <新的目录>`。
输出目录必须不存在；不覆盖、删除旧模型或旧结果。运行归档包含完整源码、
模型副本、设计文件、冻结数据摘要、日志、验证逐局记录和复现结果。

方法灵感：[炉石历史模型混合研究](https://arxiv.org/html/2303.05197v2)。
本轮是固定历史混合 PPO，不是复现其 OSFP，也不加入 AlphaStar 的专门漏洞对手。
