# 40 宠新环境：固定预算实验方案

这是 Tier 3 普通商店、Tier 4 升级依赖的模型训练，不是普通 Tier 4 商店，
也不是完整 Turtle。规则证据与尚待官方客户端复核的边界见 [规则表](MIDGAME_RULES.md)。

## 小试审查：可以进入正式实验，不代表模型已强

新模型从零训练 1,048,576 次决策，训练约 291 秒，不含所有准备/重载耗时。
三个脚本验证家族各 60 局：

| 决策数 | 平均胜场 | 十胜率 | 发生强制战斗的整局比例 |
| --- | --- | --- | --- |
| 0 | 0.05 | 0% | 100% |
| 262,144 | 2.06 | 0% | 25.0% |
| 524,288 | 2.71 | 1.1% | 28.3% |
| 786,432 | 3.24 | 0.6% | 11.7% |
| 1,048,576，最终更新后 | 4.06 | 5.6% | 1.7% |

最终模型由预先固定的验证规则选中，180 局重载逐局一致，零截断；仍有冗余
换位/冻结。三个脚本基线在同一验证分布的十胜率约 24.4–35.6%，因此小试模型
尚不如脚本。学习趋势及环境管线支持继续固定预算训练，不能据此声称泛化更强。
对手池晚期桶稀疏，正式阶段扩大池并逐模型报告实际回退，不编造后期阵容。

证据：`runs/midgame-pilot-v1/`。重复的 1,048,576 记录分别发生于最终 PPO
更新前后；报告保留两者，不能把最终更新前的指标当成最终权重的指标。

## 正式方案（成绩打开前固定）

- 保持小 Maskable PPO：学习率 0.0003、gamma=1、GAE lambda=0.95、entropy=0；
  8 个环境、每环境 256 步 rollout、batch 256；每个动作扣 0.005；30 动作强制战斗。
- 六个从零训练的对手生成者，各固定 4,194,304 步，直接取最终权重，不择优：
  训练用 stats/summon/tempo 三来源，验证用一个三脚本混合来源，测试用两个新来源
  （三脚本混合、summon+tempo）。初始化种子互不重叠，张量摘要再核验。
- 脚本池每家训练 300 / 验证 200 / 测试 400 局；历史模型池每来源训练 300 /
  验证 200 / 测试 400 局。捕获实际战斗前阵容，包含胜败，不筛选成功局。
- 三个新训练种子 17101、17201、17301，各有脚本/混合两个从零模型，每个固定
  8,388,608 次决策。混合组三脚本、三学习型来源等权，即 50/50；每场战斗
  独立抽取来源，不是每整局固定一种打法。配对初始权重
  与初始验证结果必须一致。对手生成者不作为候选初始化。
- 每 1,048,576 步验证四家族各 100 局。按平均十胜率、最弱家族十胜率、
  最低最差家族强制率、原始回报排序；精确平局留更早检查点。跨种子交付候选
  也只按验证排序，精确平局取较小种子。没有 1% 硬门槛，旧实验结论不改。
- 全部对手池在候选训练前封存；六个候选选模冻结、全部逐局重载通过后才测试。
  每模型五个测试家族各 1,000 局，共 30,000 局。报告每种子、每家族的十胜、
  强制、截断、动作数、晚期桶回退，不能只报最好模型或一个平均数。
- 配对 episode bootstrap 区间只描述固定模型/对手池上的采样不确定性，
  不冒充跨训练种子的置信区间。对手仍共享算法和沙盒生态，非所有打法泛化证明。

总训练上限约 7,550 万次决策（生成者 + 候选），最多两个本机 CPU 工作者；
不自动重试、加预算、换超参数或发布模型。每两工作者阶段最多两小时。
入口：`python -m sap_rl_lab.midgame_confirmation pipeline --output <新目录>`。
完成后仍须审查结果及失败回放、写清晰报告，不能只凭完成标记宣布项目成功。

## 完成后的证据审查（不参与选模）

`scripts/audit_midgame_confirmation.py` 只在正式流程完成后运行，输出到新目录。
它会按整局记录重新核对全部 30,000 局的胜率、强制事件/整局比例、截断、胜场、
动作数和原始回报，并检查对手池、环境版本、模型摘要及重载证据一致。
随后仅对预先由验证选出的交付候选，每家族取最早四局失败、两局成功、
一局强制/截断，去重后逐局复现，保留动作概率、价值估计与重复状态位置。
这个按结果选取的诊断样本不用于估计总体发生率，也不用于换模型。

在任何正式测试成绩打开前，另固定最多五个对照诊断案例：取正式测试中强制
整局数最多的脚本对照模型（平局取较小种子），每家族最早一局强制案例。
仍使用该模型原本由验证选中的检查点，不替换交付候选，也不增加正式测试局数。
这用于确认强制时实际在做什么，避免仅凭强制比例就断言循环原因。

第三对候选在 3,145,728 步验证仍为零胜，说明只抽查强制案例会漏掉另一类
学习失败。正式测试尚未打开时补充固定诊断规则：若某个验证所选模型在全部
测试家族合计零次十胜，额外复现其按名称排序第一个家族的最早一局，按模型、
家族、种子去重，最多六局。此规则只增加失败解释，不增加正式测试、不换模型、
不改训练预算，也不把零强制率解释为成功。零十胜本身不等于空队伍，须以回放确认。

计数器已用完成的小试全部 180 条记录检查过：stats 为 2 次十胜、2 局强制，
summon 为 3 次十胜、0 局强制，tempo 为 5 次十胜、1 局强制；全部零截断。
五项独立审查器测试覆盖错误分母、缺失记录、抽样去重与环境版本比较。

最终交付候选还会通过 `scripts/reload_midgame_archive.py`，使用封存源码在
隔离目录重新运行验证集，不打开测试集。该工具沿用已有的安全归档提取器，
另外两项测试覆盖新学习型池目录布局和数据篡改/错误目录拒绝。

## 已核对的数据覆盖限制

正式脚本训练池的三个来源合计覆盖全部 **40 种非 token 宠物**，另有 Ram
等合法商店召唤物；单个来源并不覆盖所有宠物，不能把含 token 的物种计数当成
40 宠覆盖。Tier 4 来源差异明显：例如 stats 池没有 Deer/Parrot，summon
池有较多 Deer/Whale/Parrot，Bison 则很少。这里的计数是跨回合阵容出现次数，
不是独立宠物购买次数或各组合的掌握程度。记录这一限制，不据此临时改样本或配方。

六个学习型生成者均已完成规定步数，封存池概况如下。强制比例是**生成者在
采集阵容时自身的行为**，不是候选测试成绩；所有池都包含胜败、没有截断局。

| 来源角色 | 生成局数 | 战斗前阵容数 | 有强制战斗的生成局 | 最后有数据的回合 |
| --- | ---: | ---: | ---: | ---: |
| train_stats | 300 | 4,117 | 121 | 22 |
| train_summon | 300 | 4,125 | 0 | 19 |
| train_tempo | 300 | 4,029 | 3 | 21 |
| validation_balanced | 200 | 2,717 | 0 | 20 |
| test_balanced | 400 | 5,245 | 0 | 18 |
| test_summon_tempo | 400 | 5,473 | 8 | 20 |

候选不是用这些生成者的购物动作做模仿学习，而是在线打它们留下的阵容；
因此不能把 train_stats 的高强制率直接说成候选会复制循环。但阵容仍受生成者
策略和存活回合影响，晚期桶缺失仍需在最终测试逐模型报告实际回退次数。
没有因为看到这些统计就替换生成者、筛掉失败或强制局、补造晚期阵容。

候选配对 seed17101、seed17201、seed17301 各自的起始权重及 400 局验证记录
已核对一致，三对之间初始化不同。三对六个候选均已由冻结程序实际加载核对
跑满 8,388,608 步，文件摘要一致；
17101 混合模型选中最终更新前版本，17201 混合模型选中 6,291,456 步版本；
不能拿最终更新后的分数替代所选权重的真实分数。
第三对两组跑满预算仍零胜，保留失败种子；全部模型选择已冻结，正在进行
测试前逐局重载。此处是训练完成时的状态，不代表独立测试或最终审查已完成。

因果解释限定为**整套混合对手配方**：脚本训练池合计 10,451 个阵容，额外
历史池合计 12,271 个阵容，混合组同时改变了对手类型、来源多样性和池容量。
本轮没有把这三种因素拆开做单独消融，因此即使混合组胜出，也不能断言收益
唯一来自“历史模型”本身。候选训练决策预算、初始化和其余配方保持配对一致。

## 最终状态（2026-09-08，覆盖上文的进行中状态，不改冻结方案）

六候选训练与全部 30,000 局测试已完成，流程正常退出；没有重试、扩预算或
测试后换模型。三对学习型十胜差值为 +42.55、+9.20、0 个百分点；第三对
两组都坍缩为空队伍结束回合，保留其零分。交付仍为验证选出的混合 seed17101。
全部逐局计数一致；35 个交付模型案例、5 个循环对照、2 个零胜模型案例共
42 局精确复现，封存源码重载交付模型 400 局验证一致。727 项测试通过。

最初的压力测试源文件摘要早于训练模块后续的正式实验接入，因此最终又在
封存训练源码对应的当前版本重跑同一固定压力测试：
`runs/midgame-stress-final-v1` 的 6,000 场战斗重复和 160 局完整回放均通过。
没有因此修改规则、模型或增加训练。完整结果、强制率与限制见
[简明训练报告](MIDGAME_TRAINING_REPORT.md)。所有旧小试和压力测试记录保留。
