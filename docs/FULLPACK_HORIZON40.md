# 整局安全上限：30 → 40回合

2026-09-17，用户明确授权。40仍是沙盒的计算上限，不称为官方规则。

## 资料核查

开发者的[Steam说明](https://store.steampowered.com/app/1714040/Super_Auto_Pets/)
描述Arena目标为在生命耗尽前取得10胜；[官方itch.io页面](https://teamwood.itch.io/super-auto-pets)
同样描述10胜目标，没有写30回合封顶。未找到官方30回合上限的依据；“没有计时器”
指时间限制，不能据此证明内部绝无回合上限。本次改动不依赖“官方绝无任何上限”的断言。

原代码`GameConfig.max_turns=30`是自设安全限制，与购物阶段30步、单场战斗攻击交换上限
是三件不同的事。后两者、奖励、网络隐藏层、KL、对手池均保持不变。

## 复测证据

`runs/fullpack-horizon40-audit-v1`对原模型A、原验证对手族及200个原始种子重放：

- 旧环境200局逐行复现原记录。
- 改40后，199局结果完全不变，截断由1降为0。
- 种子99000037：原30回合8胜、17平、5负而截断；新环境第34回合10胜、19平、5负，
  自然成功结束。两者均无购物强制结束。这不是策略崩坏的证据。

## 实现与恢复

新增`fullpack.horizon40.configuration`用于后续40回合训练；历史30回合源码、协议、
模型保持不动。保存的环境契约明确记录max_turns=40；独立回归覆盖30/40边界与PPO重载。

原模型时间输入为turn/30，新环境为turn/40。迁移时actor与critic的对应输入列乘4/3，
在前30回合保持相同计算意义（浮点容差内），第31–40回合允许时间特征继续增长。
这是带明确输入缩放的权重续训，新建Adam，不称为优化器/RNG精确恢复。

新目录`runs/fullpack-tier5-h40-v1`从最新可复现检查点补齐原每支2,097,152步课程预算：

- A从1,310,720步续786,432步。
- B被旧编排中断，最新保存权重为1,048,576步；从此续1,048,576步。
  其后未保存的约262,144步不伪装成已恢复。
- C尚未开始；使用同一套老师示范和BC20轮，然后训练2,097,152步。
- 总新增预算3,932,160步，CPU最多两worker，4小时有界作业；旧结果绝不覆盖。
- 保留原KL0.01、可靠性门槛与验证选模；不打开测试成绩，不改80%口径。
- 正常安全停训写入结果，不再被当作程序异常而连带杀掉其他健康候选；真实程序异常仍停止。

复用已生成的冻结对手池。超过池中最大已保存回合时，沿用既有“最近较早回合”回退，
并非声称模拟了官方晚期匹配。这次属于环境上限修正，不是重训/挑选更弱对手。
Tier5课程结果仍不能代替Tier6全开放下的80%目标。
